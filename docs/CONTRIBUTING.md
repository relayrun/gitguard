# Contributing to Git Guard

Git Guard welcomes corrections, ideas and practical feedback. Contributions in any of the eight supported languages are welcome; include the affected language when reporting a problem. This contribution guide is currently in English.

## Choose the right place

| Topic | Where to go |
| --- | --- |
| A new feature or improvement idea | [Discussions: Ideas](https://github.com/relayrun/gitguard/discussions/categories/ideas) |
| A setup or usage question | [Discussions: Q&A](https://github.com/relayrun/gitguard/discussions/categories/q-a) |
| A reproducible problem or documentation/translation correction | [Open an issue](https://github.com/relayrun/gitguard/issues/new/choose) |
| Project updates | [Discussions: Announcements](https://github.com/relayrun/gitguard/discussions/categories/announcements) |

Search existing topics first. An early idea belongs in Discussions; once its scope is agreed, an issue can track the work. A suggestion is not a delivery commitment.

## Propose a change

1. Discuss substantial changes before implementing them; small corrections can go directly to a PR.
2. Fork the repository and create a focused branch in your copy. Contributors do not need write access to this repository.
3. Make the change and check the affected links, instructions or scripts. Keep related language entries consistent and explain translation-review limits.
4. Review your diff for private information and publication rights. See [public-content review](en/public-content-review.md) and the [available checks](../scripts/README.md).
5. Open a pull request targeting `main`, explaining the problem, resulting behavior and actual verification. Keep it focused and respond to review comments.
6. A human maintainer decides whether to merge. Do not enable automatic merge or treat a submitted PR as accepted work.

Changes to reusable examples are not permission to run them against someone else's systems. Describe expected controls separately from controls verified in a specific environment.

## Review and publication

Only publish material you have the right to contribute under the repository's [MIT license](../LICENSE). Preserve required third-party notices. Do not post credentials, customer data, private repository contents or unredacted logs and screenshots. Automated checks support human review and do not prove the absence of all sensitive information.

Be respectful and follow the [community guidelines](CODE_OF_CONDUCT.md). Maintainers may ask for revisions, move a topic to a more suitable category or decline a change that does not fit the project.
