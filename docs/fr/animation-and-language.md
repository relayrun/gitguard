La courte présentation suit cet ordre : marque, risques du dépôt, frontières de permissions testées, configuration visible assistée par l’IA, puis quatre relais quotidiens. Elle illustre la méthode sans certifier un serveur réel. Le processus écrit fait référence ; Git.md dans un dialogue d’exemple désigne le véritable document de procédure de l’utilisateur.

<a id="homepage-placement-and-language"></a>

## Position et langue sur la page d’accueil

Placez la présentation de 40 secondes juste après la liste des langues du README, avant l’introduction centrale et les quatre étapes quotidiennes. Le titre anglais est « Git Guard in 40 seconds » ; le titre chinois est « 40 秒了解 Git Guard ». C’est une présentation du produit, pas le tutoriel complet de configuration.

Utilisez la langue du README sélectionné. Le README anglais par défaut renvoie au MP4 anglais ; le chinois simplifié et le japonais renvoient chacun au leur. N’ajoutez pas de second sélecteur de langue pour la vidéo. Changer de README sélectionne aussi sa vidéo. Allemand, français, espagnol, portugais brésilien et russe utilisent également leurs films terminés. Les huit paires README/vidéo sont incluses dans ce paquet local.

<a id="delivery-and-playback"></a>

## Format de livraison et lecture

- Distribuez uniquement des MP4. Conservez les couvertures PNG comme fichiers réutilisables, sans GIF animé. Les compositions modifiables, éléments communs et traductions restent dans l’espace de production ; seuls les exports retenus sont distribués.
- Chaque README GitHub intègre la vidéo de sa langue grâce à une URL de pièce jointe placée seule dans un paragraphe, puis conserve un lien de téléchargement direct du MP4. Les notes des médias répertorient les MP4 fournis et les pièces jointes par langue. D’autres lecteurs Markdown peuvent afficher uniquement un lien.
- Un README ne peut pas exécuter de JavaScript personnalisé ni choisir une vidéo selon la langue du navigateur ou l’adresse IP. Les couvertures liées ouvrent des fichiers ; les balises HTML video ordinaires sont filtrées. Autorisez la publication avant de remplacer une pièce jointe, vérifiez la lecture réelle et actualisez ensemble le README et la table. GitHub gère le lecteur ; lecture automatique, boucle et maintien de la dernière image ne sont pas garantis.
- Sur un site, résolvez la langue par URL explicite, choix manuel mémorisé, préférences de contenu du navigateur prises en charge, puis anglais par défaut. Choisissez la vidéo disponible correspondante selon cette même langue. Un menu vidéo séparé est inutile. Indiquez clairement un repli anglais et ne présentez pas le chinois simplifié comme une traduction en chinois traditionnel.
- La lecture Web commence en mode muet. Activez les effets uniquement sur un clic explicite ; gardez pause/silence, couverture/lecture manuelle de secours et prise en compte des préférences de mouvement réduit. La lecture normale finit sur l’image finale, avec reprise et boucle facultative. Sans JavaScript, conservez les liens MP4 ordinaires.
- Les huit exports actuels durent 40 secondes, avec de brefs effets d’action et sans musique de fond. Préservez toute l’animation finale de la marque, puis le carton immobile ; ne collez pas le début à la fin.
- Utilisez des noms prévisibles comme RelayRun-GitGuard-Intro-en-v12.mp4 et les équivalents zh-CN, ja, de, fr, es, pt-BR et ru. Voir les [vidéos et crédits sonores](../../assets/videos/README.md).

<a id="before-adding-media-to-a-release"></a>

## Avant d’ajouter des médias à une publication

Examinez images exportées, textes, métadonnées et droits des ressources. Vérifiez durée complète audio/vidéo, décodage, taille mesurée et liens linguistiques. La lecture dans un vrai navigateur est distincte des contrôles de fichiers ; les mesures audio ne remplacent pas une écoute. Une alerte de binaire ou de taille du scanner exige une revue manuelle ciblée ; ne désactivez pas globalement ces alertes.

Livrez uniquement les exports choisis et crédits nécessaires. Sources modifiables, preuves privées, enregistrements bruts et plans internes n’appartiennent pas au paquet public. Une prévisualisation locale approche la présentation sans certifier le rendu GitHub. Téléversement de pièces jointes publiques, intégration au site et déploiement sont des actions séparées.
