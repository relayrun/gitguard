<a id="configure-the-public-content-check"></a>

## 公開内容チェッカーの設定

1. 対象プロジェクトと公開するファイルの範囲を正確に決めます。内部記録、資格情報、非公開のスキャナー設定、診断出力は公開ツリーの外に置きます。開発ディレクトリに非公開情報がある場合は、別の公開用コピーを点検します。検出をゼロにするためだけに非公開の原本を削除してはいけません。
2. Git Guard のソース、またはインストールしたスキルに同梱された参照スナップショットでチェッカーを探します。Python 3.9 以降と標準ライブラリが必要です。自動インストール、サービス起動、サーバー権限の強制は行いません。対象を `--root` で明示します。スキルのインストール先は対象プロジェクトではありません。
3. 導入先のプロジェクトでは `--profile generic` を使います。`--profile gitguard` は、このパッケージ固有の公開・非公開ディレクトリの除外規則も適用する場合に限ります。付属チェッカーには独自の機密語リストや自動置換機能はありません。組織固有の秘密や識別子は、公開ツリー外に設定を保管した適切な別のスキャナーで検査します。[非公開の照合リスト](#sensitive-matching-lists-stay-private)も参照してください。
4. 作業ファイル、ステージ済みのバイト列、送出履歴は別々に調べます。以下のパスは仮の例です。履歴範囲は実際に送るコミットに置き換えます。チェッカーは fetch も push もしません。Git リポジトリがない場合は作業ファイルから始め、インデックスや履歴が存在する段階で追加確認します。作業ファイルだけの検査は後のコミットを保証しません。

```sh
python3 -B /path/to/gitguard/scripts/check_public_content.py --root /path/to/public-project --profile generic
python3 -B /path/to/gitguard/scripts/check_public_content.py --root /path/to/public-project --profile generic --staged
python3 -B /path/to/gitguard/scripts/check_public_content.py --root /path/to/public-project --profile generic --history origin/main..HEAD
```

<a id="interpret-results-and-handle-findings"></a>

## 結果の読み方と検出事項への対応

終了コード **0** は実装済み規則の範囲で検出なし、**1** は確認が必要な検出あり、**2** は検査未完了です。レポートはパス・分類・行番号を示し、一致した秘密の値は表示しません。作業ファイルの検査は Git メタデータ以外の無視されたファイルも含みます。無視設定は、公開物への誤コピーを防ぐものではありません。

規則は秘密鍵の特徴、一部の GitHub トークン形式、URL 内の資格情報、マシン固有パス、プライベートネットワークのアドレス、一部の非公開・実行時ファイル名、壊れた相対 Markdown リンクや範囲外へ出るリンクを検出します。全てのパスワードやアカウント識別子を検出するわけではありません。バイナリーは人の点検が必要です。2,000,000 バイトを超えるファイルの内容は検査せず、ファイル数の上限は 3,000、履歴範囲の上限は 200 コミットです。宣言した対象が大きい場合は分割して調べ、黙って省いてはいけません。

検出ごとに分類・場所・判断・再検査結果を記録し、機密値は転記しません。公開用コピーや収録規則を修正するか、無害または手動確認済みと判断した根拠を記録してから、該当する作業ファイル・ステージ・履歴を再検査します。バイナリーやサイズの通知を全体で抑制してはいけません。実際に資格情報が漏れた場合は交換し、別途許可を得た履歴修復が必要です。このツールは履歴を修復せず、内容を削除・置換しません。タイムアウトや未完了の検査は合格ではありません。

この Git Guard の配布物は、まず `scripts/prepare_release.py` で範囲を明示した公開用コピーを作成します。開発用キャッシュは元の場所に残し、除外項目を別途記録します。任意の `--media-review` は、個別に確認した PNG/MP4 と正確な SHA-256 を記載した非公開の記録を読みます。一致するバイナリ確認事項だけを確認済みとして別に報告し、変更されたファイル、秘密情報、読み取り不能、サイズ超過は未解決のままです。終了コード 0 には記録済みのメディア確認が含まれる場合がありますが、自動的なプライバシー認証ではありません。[検査・パッケージ化の説明](../../scripts/README.md)を参照してください。

<a id="before-a-local-commit"></a>

## ローカルコミットの前

未追跡ファイルも含め、実際の変更を調べます。所有権と公開する権利を確認します。非公開の計画、ホスト・ユーザーのパス、内部アドレス、トークン、秘密鍵、資格情報、顧客データ、未加工の画面写真・ログ、無関係な製品ソースを除きます。例には一般的な名前と値を使います。

リンク、UTF-8 テキスト、意味のある言語対応、第三者の権利表記、完了状況の正確さを確認します。計画段階のサイトやデプロイを利用可能と説明してはいけません。非公開の証拠は公開ツリーの外に置きます。

作業ファイルとステージ内容は異なる場合があるため、ステージされたバイト列を別に調べます。名前変更・削除、バイナリー、サブモジュール、シンボリックリンクを確認します。見えている文書が安全でも、埋め込まれた添付が安全とは限りません。ローカルコミットは公開の許可ではありません。

<a id="before-a-push"></a>

## push の前

意図した送信先に対して送るコミットを正確に列挙し、削除済みファイルも含めて各対象スナップショットを点検します。後で削除しても、以前の秘密情報は履歴に残ります。タグや他の参照は、予定する push に含まれる場合に確認します。新しいリポジトリに非公開履歴を誤って引き継いではいけません。

機密情報をコミットしていた場合、公開を止め、適切な資格情報の交換と別途承認された修復を行います。履歴を隠すために黙って force-push したりリポジトリを削除したりしてはいけません。自動スキャナーは補助的な証拠であり、全ての非公開情報が除去された証明ではありません。

<a id="reviewable-release"></a>

## 確認可能な公開内容

送信先、公開範囲、変更ファイル、送出履歴、権利・ライセンスの判断、検査、残る制約を記録します。その具体的な操作に対する既存の許可を確認し、人による最終マージを保ちます。

公式サイトにリンクするリポジトリでは、ホスト名、HTTPS 証明書、ブランド、実際のページを確認します。各言語 README の表示ラベルを一貫して翻訳し、正規の行き先は同じにします。許可された公開作業でリポジトリの Website 欄も確認します。手順書はサイトに依存せず役立つ内容を維持します。

<a id="evidence-levels"></a>

## 証拠の段階

「確認済み」「静的検査済み」「動作テスト済み」「デプロイ済み」「ユーザー確認済み」を分けます。設定の画面写真、スキャナーの終了状態、転送成功を実機の安全性・復元の証明に置き換えてはいけません。権限は[検証仕様](security-acceptance.md)に従います。

<a id="sensitive-matching-lists-stay-private"></a>

## 機密情報の照合リストは非公開にする

公開するのは再利用できる検査ロジックと架空のテストデータだけです。実際の秘密、アカウント識別子、プロジェクト固有の照合・置換リストは、ソース、スキルパッケージ、ダウンロード、画面写真、送出 Git 履歴の外に保持します。実際の秘密をそのまま含むルール自体も機密です。スキャナー設定に置いても公開可能にはなりません。無視ルールはステージ内容と履歴の確認を代替しません。

Gitleaks など別のスキャナーに非公開設定を使う場合、実行時に非公開の場所から渡します。公開パッケージへコピーせず、一致値を出力せず、実値をコマンドライン引数やテストデータに入れません。診断ファイルも非公開に保ち、共有前に内容を除去します。

付属チェッカーは Git Guard 用に新しく作ったものです。既存の非公開リストを読み込まず、取引・顧客アカウント、任意のパスワード、全種類のトークンを個別に認識するものではありません。一般的な検出規則は、プロジェクトに適したスキャナーと人の点検を補助します。検出ゼロは完全な機密除去の証明ではなく、履歴の消去も実行しません。
