この仕様は人向け手順書と今後のスキルで共用します。これは検証計画であり、導入環境の合格報告ではありません。OneDev の詳細設定と GitHub の対応ガイドは、矛盾する基準を別に定めず、この仕様を参照します。

<a id="inspect-first"></a>

## 最初に調査する

プラットフォームとバージョン、公開範囲、保護ブランチ、アカウント、役割、トークン・アプリの権限、継承されたルール、適用順序・強制状態、例外を記録します。関連する Git/SSH/HTTPS、Web、API、CI・連携、プロキシ、ホスト・ストレージの経路を調べます。人の既存ブラウザーセッションや資格情報を AI も使える状態になっていないか確認します。

自前で運用する場合、ホスト、コンテナ、データディレクトリへのアクセスと代替ポートを確認します。独立サーバーや NAS が有効な境界になるのは、AI が管理できない場合です。リバースプロキシが制御するのはそこを通るリクエストだけであり、別の公開経路や実データは保護しません。ホスティングサービスでは、自前プロキシの方式をそのまま適用できると考えず、サービス固有のアカウント・アプリ制御を使います。

<a id="test-only-in-the-authorized-environment"></a>

## 許可された環境だけでテストする

別途許可された使い捨てのリポジトリまたはインスタンスに、代表的なルールと別々のアカウントを設定します。テストデータを復元できること、許可される操作の期待結果を確認します。拒否動作のテストはその使い捨て対象だけで行い、無害な内容を使って証拠を保存します。この文書は本番リポジトリの削除、実際の履歴の書き換え、稼働中の役割変更を許可するものではありません。

<a id="acceptance-matrix"></a>

## 検証表

| 機能・経路 | 制限された AI アカウントの期待結果 | 必要な証拠 |
| --- | --- | --- |
| 許可された作業ブランチの読み取り・準備 | 範囲内で許可 | 正常系の操作が意図したサービスとアカウントに到達する |
| 保護された main へ新規コミットを通常の push で直接送信 | 方針により拒否 | 実際の拒否と保護参照が変化していないこと |
| 保護履歴への force-push | 拒否 | 権限による拒否と履歴が変化していないこと |
| 保護ブランチ・参照の削除 | 拒否 | 実際の拒否と参照の存続 |
| リポジトリ・プロジェクトの削除 | 拒否 | 使い捨てプロジェクトが残り、アカウントに実効的な削除権限がないこと |
| 必須の人間レビュアーに代わる承認 | 拒否 | レビュー担当アカウントと許可の記録 |
| レビュー通過後を含む最終マージ | 人だけがマージする方針では拒否 | 実際の権限判定。未承認 PR だけでは検証不足 |
| 自動マージや同等の連携の有効化・使用 | この手順では AI に拒否 | API/Web/アプリの経路と実際の操作者 |
| 役割、保護、例外一覧、安全検査の変更 | 拒否 | 前後の設定と拒否結果 |
| 別の資格情報、セッション、エンドポイント、CI 経路 | 意図しない権限がない | 各経路の一覧と範囲を限定したテスト。不明な経路は未検証 |
| ホスト、コンテナ、リポジトリ実データの変更 | 管理・破壊的アクセスがない | アプリのチェックボックスだけでなく OS・ストレージの境界の証拠 |
| 全復元ポイントの削除・上書き | 開発アカウントには拒否 | 独立した保持とバックアップ管理の境界 |
| 人によるレビューと意図したマージ | レビューポリシーに従い許可 | 本人のアカウントを使った正常系の検証 |

方針に影響するブランチ・タグの作成、タグ削除、ブランチ固有の例外も確認します。準備作業をすべて誤って止めた状態を、役割分離の成功としないでください。

<a id="record-each-result"></a>

## 結果を一件ずつ記録する

各行について、テストアカウント、ソフトウェア・設定の識別情報、ソース・対象、操作と経路、期待結果、実際の結果・理由、操作前後の対象状態、時刻、証拠の場所を残します。共有前に資格情報と無関係な非公開データを除去します。

**合格・不合格・未検証**と説明を使います。タイムアウト、ログイン失敗、競合、不正なリクエスト、WIP 表示、サーバー停止、スクリーンショット、有効なスイッチだけでは、意図した権限による拒否を証明できません。正常系のテストは、権限制御とテスト環境の故障を区別する助けになります。

必須の境界に未検証や不合格があれば、明確に報告します。あらゆる AI のミスをなくしたと言わず、実際に遮断した操作を示します。役割、プロキシ、ルール、バージョン、連携を変更したら影響する経路を再検証し、以前の証拠は元の適用範囲とともに保持します。
