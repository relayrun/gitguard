Введение, быстрый старт, все семь подробных руководств и видео доступны на русском. OneDev и GitHub — примеры; принципы можно адаптировать к другим платформам Git. Перевод предназначен для проверки и не заменяет проверку реальных прав.

До разрешённого коммита или отправки следуйте руководству: [настройте и запустите проверку](public-content-review.md#configure-the-public-content-check), затем [интерпретируйте и обработайте находки](public-content-review.md#interpret-results-and-handle-findings).

## ИИ может помочь с настройкой

Следуйте руководству самостоятельно либо передайте его и нужный навык помощнику. **Предпочтителен Computer Use с видимым интерфейсом:** наблюдайте за действиями, выдавайте необходимые для задачи права, вводите секретные данные сами. После настройки завершите временный административный сеанс и верните ИИ ограниченную повседневную учётную запись.

| Среда | С чего начать |
| --- | --- |
| Собственный OneDev | [Руководство](onedev.md) · [Навык настройки и приёмки (английский)](../../skills/gitguard-onedev-safety/SKILL.md) |
| GitHub | [Руководство GitHub](github.md) |
| Другие платформы Git | Сопоставьте [общий процесс](workflow.md) и [матрицу приёмки](security-acceptance.md) с их правами и интерфейсами. |

Первичная настройка включает четыре части: определить репозиторий, main и отдельные учётные записи; настроить ограничения; проверить разрешённые и запрещённые действия в согласованном изолированном тестовом репозитории; организовать [резервное копирование и восстановление](backup-and-recovery.md). Повторять всё при каждом изменении не нужно. Перепроверяйте затронутые части при изменении прав, правил или среды.

## Четыре повседневных шага

Используйте [навык совместной работы (английский)](../../skills/gitguard-workflow/SKILL.md) и Git-процесс вашего проекта.

| Шаг | Что вы говорите или делаете | Что делает ИИ |
| --- | --- | --- |
| 1. Локальный коммит | «Выполни шаг 1 по Git.md». | Читает правила, проверяет изменения и создаёт локальный коммит. На сервер пока ничего не отправляется. |
| 2. Push и подготовка | «Выполни шаг 2 по Git.md». | Отправляет разрешённую рабочую ветку, готовит заголовок, описание и результаты проверок. |
| 3. Проверка и слияние человеком | Создайте запрос в веб-интерфейсе; проверьте исходную и целевую ветки, заголовок, описание, изменения и проверки; затем выполните слияние. | Предоставляет пояснения и помощь. Окончательное слияние выполняет человек. |
| 4. Завершение после слияния | «Я выполнил слияние. Проверь результат и сделай уборку». | Проверяет фактически включённый код, безопасно синхронизирует main и удаляет только подтверждённо завершённые ветки. |

`Git.md` означает реальный документ процесса в вашем проекте; имя может отличаться. Вы решаете, когда делать коммит, push и слияние. [Полный процесс](workflow.md)

## Защита и восстановление

Наличие настроек не доказывает действенность защиты. Испытания отказа выполняются только с отдельным разрешением в одноразовом тестовом репозитории; непроверенные пути отмечаются явно. Нужны независимая синхронизация и защищённые исторические точки восстановления. Чистая сборка и запуск программы — дополнительные проверки по выбору проекта.

В примере OneDev подтверждённый адрес автора может влиять на предложение исходной ветки, а не выполнять слияние. Префикс WIP в заголовке блокирует слияние в рассматриваемой версии; это не запрет любых заголовков, начинающихся с латинской буквы.
