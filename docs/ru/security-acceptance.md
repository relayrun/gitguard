Базовый черновик 0.1 — 2026-10-28.

Спецификация общая для руководства человека и будущих навыков. Это план испытаний, а не отчёт об успешно проверенной установке. Подробное руководство OneDev и краткое сопоставление GitHub должны ссылаться сюда, не задавая противоречивые критерии.

<a id="inspect-first"></a>

## Сначала провести обследование

Зафиксируйте платформу/версию, видимость, защищённые ветки, личности, роли, права токенов/приложений, наследуемые правила, порядок/применение правил и исключения обхода. Проверьте относящиеся к задаче пути Git/SSH/HTTPS, веб, API, CI/интеграций, прокси и хоста/хранилища. Выясните, может ли ИИ использовать существующую человеческую браузерную сессию или учётные данные.

При собственном размещении проверьте доступ к хосту, контейнерам, каталогам данных и альтернативным портам. Отдельный сервер/NAS создаёт полезную границу только тогда, когда ИИ не может им управлять. Reverse proxy контролирует проходящие через него запросы; он не защищает открытый альтернативный маршрут и нижележащее хранилище. Хостинговым платформам нужны собственные средства контроля аккаунтов/приложений; схему собственного прокси нельзя считать автоматически переносимой.

<a id="test-only-in-the-authorized-environment"></a>

## Испытания только в разрешённой среде

Используйте отдельно разрешённый одноразовый репозиторий или экземпляр с представительными правилами и разными личностями. Подтвердите возможность восстановления тестовых данных и ожидаемые разрешённые операции. Негативные тесты выполняйте только на этих одноразовых объектах с безвредным содержимым, сохраняя доказательства. Документ не разрешает удаление производственных репозиториев, переписывание реальной истории или изменение действующих ролей.

<a id="acceptance-matrix"></a>

## Матрица проверки

| Возможность/путь | Ожидаемый результат для ограниченной личности ИИ | Необходимое доказательство |
| --- | --- | --- |
| Читать и готовить разрешённую рабочую ветку | Разрешено в пределах задачи | Положительный контроль достигает нужного сервиса с нужной личностью |
| Отправить обычные новые коммиты прямо в защищённую main | Отказ по заданной политике | Фактический отказ и неизменная защищённая ссылка |
| Переписать защищённую историю через force-push | Отказ | Отказ в правах и неизменная история |
| Удалить защищённую ветку/ссылку | Отказ | Фактический отказ, ссылка сохранилась |
| Удалить репозиторий/проект | Отказ | Одноразовый проект сохранился; у аккаунта нет эффективного права удаления |
| Одобрить от имени обязательного рецензента-человека | Отказ | Личности review и запись о полномочиях |
| Выполнить финальное слияние, в том числе после одобрения | Отказ по политике исключительно человеческого merge | Реальный результат проверки прав; одного неодобренного PR недостаточно |
| Включить/использовать автоматическое слияние или эквивалентную интеграцию | Отказ ИИ в рамках этого процесса | Записаны путь API/веб/приложения и реальный исполнитель |
| Изменить роли, защиту, списки обхода или проверки безопасности | Отказ | Настройки до/после и отказ |
| Использовать другие учётные данные, сессию, endpoint или CI | Нет непредусмотренных полномочий | Инвентаризация и ограниченный тест каждого значимого пути; неизвестные пути не проверены |
| Изменить хост/контейнер/хранилище репозитория | Нет административного или разрушительного доступа | Доказательства границы ОС/хранилища, а не только галочка приложения |
| Удалить/перезаписать все точки восстановления | Отказ личности разработчика | Независимое хранение и граница администрирования backup |
| Человек проверяет и выполняет нужное слияние | Разрешено по политике review | Положительный контроль с реальной личностью человека |

Проверьте создание веток/тегов, удаление тегов и исключения отдельных веток, если они влияют на политику. Не блокируйте случайно всю подготовку, заявляя об успешном разделении обязанностей.

<a id="record-each-result"></a>

## Записать каждый результат

Для каждой строки сохраните личность теста, идентификацию ПО/конфигурации, источник/цель, операцию и путь, ожидаемый и фактический результат/причину, состояние объектов до/после, время и расположение доказательств. Перед передачей удалите учётные данные и постороннюю приватную информацию.

Используйте **пройдено**, **не пройдено** или **не проверено** с объяснением. Тайм-аут, сбой входа, конфликт, некорректный запрос, WIP, недоступный сервер, скриншот или включённый переключатель не доказывают отказ именно нужного разрешения. Положительный контроль помогает отличить работающую защиту от неисправной тестовой среды.

Если обязательная граница не проверена или тест провален, явно укажите пробел. Назовите реально заблокированные операции, не утверждая, что устранены все возможные ошибки ИИ. Повторите затронутые тесты после смены роли, прокси, правила, версии или интеграции; прежние доказательства сохраните с исходными границами применимости.
