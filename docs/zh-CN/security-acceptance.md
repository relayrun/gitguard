# 安全验收规范

基础指南审阅稿 0.1 — 2026-10-28。

本规范供人工手册和后续技能共用，是验收要求，不是某台环境已经通过的报告。OneDev 详细设置教程和 GitHub 简要对照均引用这里，不另写互相冲突的标准。

<a id="inspect-first"></a>

## 先只读检查

记录平台与版本、仓库公开性、受保护分支、身份角色、令牌与应用权限、继承规则、匹配顺序、生效状态和绕过例外。覆盖相关 Git、SSH、HTTPS、网页、API、CI、代理及宿主机和存储路径，也检查 AI 能否使用已经登录的人工网页会话或凭据。

自建部署还要检查宿主机、容器、数据目录及其他服务端口。独立服务器或 NAS 只有在 AI 不能管理它时才形成有用边界。入口代理只约束经过它的请求，不能保护另一个开放入口或底层存储。线上托管平台应使用其身份、应用与平台权限，不照搬自建代理配置。

<a id="test-only-in-the-authorized-environment"></a>

## 只在获准的环境中测试

使用另行授权的隔离测试库或实例，配置有代表性的规则，并使用不同身份。先确认测试数据可恢复、应允许的操作正常。拒绝测试只针对这些可丢弃对象，使用无业务影响的内容并保留证据。本文不授权删除生产仓库、改写真实历史或调整现有账号权限。

<a id="acceptance-matrix"></a>

## 验收矩阵

| 操作或路径 | 对受限 AI 身份的预期 | 所需证据 |
| --- | --- | --- |
| 读取并准备允许的功能分支 | 在范围内允许 | 正向对照证明身份和服务有效 |
| 普通追加提交直接推入受保护主线 | 被目标策略拒绝 | 真实拒绝原因及主线引用未变 |
| 强推并覆盖受保护历史 | 拒绝 | 权限拒绝及历史未变 |
| 删除受保护分支或引用 | 拒绝 | 真实拒绝且引用仍在 |
| 删除仓库或项目 | 拒绝 | 隔离项目仍存在，身份没有有效删除权限 |
| 冒充所要求的人工审核身份批准 | 拒绝 | 审核身份和权限记录 |
| 最终合并，包括审核已经通过的情况 | 按人工专属策略拒绝 | 真实权限结果；仅测试未获批准的 PR 不足 |
| 启用或使用自动合并、等效集成 | 本流程下不允许 AI 使用 | 网页、接口、应用路径及实际身份 |
| 改角色、保护、绕过名单或安全检查 | 拒绝 | 配置前后状态及拒绝结果 |
| 使用其他凭据、会话、端口或 CI | 不得出现额外权限 | 相关路径清单与逐项测试；未知项仍未验证 |
| 修改宿主机、容器或仓库底层数据 | 不得有管理或破坏性访问 | 系统与存储权限证据，不能只看应用开关 |
| 删除或覆盖全部恢复点 | 开发身份不得有此权限 | 独立历史保留和备份管理边界 |
| 人工审核并执行预期合并 | 符合审查规则时允许 | 使用真实人工身份的正向对照 |

按项目策略补查分支或标签创建、标签删除及特殊分支例外。不能因为完全禁止了正常准备工作，就声称职责分离成功。

<a id="record-each-result"></a>

## 逐项记录结果

每项保留测试身份、版本和配置身份、源与目标、操作及路径、预期、实际结果与原因、前后状态、时间和证据位置。分享证据前去除凭据和无关私人信息。

结果使用“通过”“失败”“未验证”并说明原因。超时、未登录、冲突、无效请求、WIP 标记、服务不可用、截图或开关已启用，均不能单独证明预期权限限制有效。正向对照有助于分清权限阻断与测试环境损坏。

必要边界未测试或失败时，应明确留下缺口。说明实际拦住了哪些操作，不承诺杜绝所有 AI 误操作。角色、代理、规则、版本或集成变化后只复测受影响路径，历史证据保留原范围。
