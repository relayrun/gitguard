# Example agent entry for an adopting project

Adapt this entry to the project's own real documentation paths before use.

1. Read the project's development agreements, current work and documentation index.
2. Read its Git workflow before a Git write; use authorization already given for the concrete action.
3. Keep local preparation, authorized branch/PR sharing and the human final merge distinct.
4. Apply the Git Guard workflow and acceptance skill only within the current project and authorized scope.
5. Keep management records and private data out of public release material unless deliberately reviewed for publication.

Point to authoritative project documents instead of copying multiple versions of the same rules. This sample is not Git Guard's own private project entry.
